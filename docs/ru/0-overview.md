# Библиотека buildtool

Библиотека `buildtool` — инструмент сборки нативного кода для языка Yukino и сборочных скриптов `build.ykn`. Она предоставляет высокоуровневый и эргономичный программный интерфейс для автоматической компиляции исходных файлов на C, C++ и Rust, упаковки их в статические библиотеки (`.a`) и автоматической передачи директив линковщику Yukino.

---

## 1. Подключение: load buildtool

Библиотека используется в предсборочном скрипте `build.ykn`. Чтобы подключить ее, добавьте запись в секцию `[libs.build]` манифеста `yuki.toml`:

```toml
[libs.build]
buildtool = { git = "https://github.com/shareui/buildtool", tag = "v0.1.0" }
```

Или по локальному пути:

```toml
[libs.build]
buildtool = { path = "../libs/buildtool" }
```

### Импорт в коде build.ykn

```yukino
load buildtool: cc, rust
```

Доступные сущности:
- **Функции создания билдеров:** `cc()`, `rust()`.
- **Вспомогательные функции вывода директив:** `emit_link_archive`, `emit_link_system`, `emit_warning`.
- **Проверки тулчейна:** `find_c_compiler`, `find_cpp_compiler`, `find_ar`, `find_rustc`, `find_cargo`.
- **Структуры ошибок:** `ToolchainError`, `CompilationError`, `ConfigError`.

---

## 2. Архитектура и принцип работы

Скрипт `build.ykn` запускается компилятором `yukino` перед началом сборки приложения. Библиотека `buildtool`:
1. Автоматически находит доступный компилятор в системе (для C/C++ поддерживаются `clang` и `gcc`; для Rust — `rustc` и `cargo`).
2. При отсутствии компилятора выбрасывает понятную ошибку с рекомендацией по установке.
3. Компилирует исходные файлы с флагом `-fPIC` и оптимизациями.
4. Упаковывает скомпилированные объектные файлы в статический архив (`lib<имя>.a`) с помощью утилиты `ar`.
5. Автоматически отправляет сборочные директивы через стандартный вывод:
   - `yuki:link-archive=...` — передает статический архив `.a` (или объектный файл `.o`) линковщику.
   - `yuki:link-system=stdc++` — при сборке C++ исходников автоматически подключает стандартную библиотеку C++.
6. Компилятор Yukino перехватывает эти директивы и линкует созданные нативные библиотеки в бинарный файл вашего приложения.

## 3. Структуры ошибок

При возникновении неполадок библиотека вызывает `panic` со строгими типизированными структурами. Это позволяет безопасно перехватывать их через `sus / catch`.

```yukino
public struct ToolchainError {
    tool: string
    message: string
    code: int32
}

public struct CompilationError {
    message: string
    command: string
    output: string
    code: int32
}

public struct ConfigError {
    message: string
    code: int32
}
```

Коды ошибок:
- `1001`: Не найден C-компилятор (`clang` или `gcc`).
- `1002`: Не найден C++-компилятор (`clang++` или `g++`).
- `1003`: Не найдена утилита создания архивов `ar`.
- `1004`: Не найден компилятор `rustc`.
- `1005`: Не найден пакетный менеджер `cargo`.
- `2001`: Не указаны исходные файлы для C/C++.
- `2002`: Ошибка компиляции файла C/C++.
- `2003`: Ошибка создания статического архива утилитой `ar`.
- `3001`: Ошибка выполнения `cargo build`.
- `3002`: Артефакт сборки Cargo не найден.
- `3003`: Ошибка компиляции `rustc`.
- `3004`: Не указан исходный файл Rust или путь к `Cargo.toml`.
